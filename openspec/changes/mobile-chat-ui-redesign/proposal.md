# 移动端聊天界面视觉升级 — Proposal

## 背景

当前 `ScreenChat` 的移动端聊天界面采用输入框上方横排快捷按钮的方式，入口过多、视觉拥挤。用户参考"灵光"类 AI 助手截图，希望升级为更沉浸、更聚焦的输入体验。

## 目标

1. 聚焦输入框时呈现沉浸式推荐态（参考图 2）。
2. 重构输入框：语音输入移入输入框内，左侧加 + 号按钮，点击展开底部操作面板（参考图 3）。
3. 聊天区域顶部增加"Hi, 老板"推荐输入区，支持随机换一批。
4. 推荐文案结合现有能力：推荐方案生成、预算评估、市场分析、创建盟域、创建活动、产品海报、产品视频等。

## 范围

### 在范围内
- `frontend/src/pages/mobile-workbench/ScreenChat.tsx` 的 UI/UX 重构。
- 复用现有 `/upload`、virtual message（图片/视频）、模板填充、`onNavigate('brief')` 等能力。
- 推荐输入的本地预设数组 + 随机打乱。

### 不在范围内
- 不新增后端 API 端点。
- 不新增意图类型或修改意图识别逻辑。
- 不改动桌面端 `ChatContainer`。
- 不实现"创建盟域/创建活动"的独立工作流，仅通过自然语言触发现有方案生成链路。

## 关键决策

| 问题 | 决策 |
|------|------|
| "创建盟域/创建活动"如何响应？ | 作为普通文本消息发送，由意图识别走 `generate_plan`/`clarify`，不新增 intent。 |
| 推荐输入区显示时机？ | 空会话且输入框聚焦时显示；有历史消息时保持现有聊天区域。 |
| "换一批"实现？ | 前端本地预设数组随机打乱，MVP 不走接口。 |
| + 号面板与键盘？ | 键盘拉起时强制收起 + 号面板；点击 + 号时如果键盘已收起则展开，如果键盘拉起则先失焦收起键盘再展开。 |
| 语音/发送切换？ | 输入框为空时显示麦克风图标，有文字时显示发送按钮。 |
| 是否拆组件？ | `ScreenChat.tsx` 当前约 250 行，新增逻辑预计增至 450-550 行，按 ponytail 原则先内联，超过 800 行再拆分。 |
| 是否需要 OpenAPI YAML？ | 否，本次为纯前端 UI/UX 改动，不涉及后端契约变更。 |

## 参考风格

- 暗色主题、圆角、半透明毛玻璃面板。
- 保持现有移动端 workbench 的渐变按钮和卡片风格。
- 推荐卡片使用浅色文字 + 图标，与图 2 类似但颜色沿用品牌色。

## 风险

1. 软键盘高度变化可能导致输入框/面板位置跳动，需要真机或模拟器验证。
2. 沉浸式聚焦态会遮挡历史消息，需明确显示时机。
3. 底部面板与系统手势返回可能冲突，需测试 iOS Safari 底部安全区。
